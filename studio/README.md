# MINI CITY 4.2.4 — Папки категорий и пронумерованные модели

**Смысл исправления по пользовательской приёмке:** прежде каталог показывал
все семь типов объектов в одном плоском списке. Пользователь запросил
иерархию: **каталог категории → внутри отдельные пронумерованные,
отличающиеся друг от друга модели этой категории**.

### Как работает
1. `studio/catalog.html` сначала показывает пять **папок категорий**:
   здания, персонажи, улицы и окружение, растительность, городские предметы.
   На папке указано количество **различных моделей/типов**, а не инстансов.
2. Нажатие на папку открывает **только её модели**, номер `№ 001`,
   `№ 002` и т. д., название, реальный исходник, состояние и ссылки на
   проверочные сцены. Число присвоено полем `modelNumber` и **не должно
   меняться при добавлении/удалении/сортировке других моделей**.
   Допускается `№ 001` одновременно в разных папках, но **не два раза
   внутри одной** — это валидирует `models/catalog-utils.js`.
3. Кнопка «Все каталоги» возвращает к папкам, адрес `?category=character`
   открывает папку персонажей напрямую, браузерные Back/Forward
   синхронизируют экран без перезагрузки.
4. Внутри папки есть поиск по названию/номеру/исходнику и фильтрация
   по состоянию. Создание и перезапись моделей через браузер **не
   реализованы**, каталог отражает подтверждённую версию в Git.
5. Папка «Персонажи» содержит **две действительно разные** модели:
   `№ 001` — анимированный городской кандидат (внешний GLB),
   `№ 002` — запасная неанимированная анатомическая модель (локальный GLB).
   Папка «Городские предметы» — `№ 001` фонарь и `№ 002` скамейка.
   Здания — пока **`№ 001` пятиэтажка**, не рисуем фиктивный дом № 002.
   Деревья — пока **один модельный тип № 001**, 22 экземпляра
   этой одной модели на карте. Другой тип дерева получит № 002 только
   после фактической разработки.
6. Никакой новый GLB и никакая копия игровой сцены не добавлены.
   Производительность в игре не должна измениться из-за этой
   каталоговой страницы; реальные FPS подтверждаются только на iPhone.

### Тесты
- `node models/test-catalog.mjs`: схема v2, пять папок, пер-категорийные
  уникальные стабильные номера, типы/количество копий, реальные пути.
- `node studio/test-catalog.mjs`: двухуровневый HTML, ссылки,
  отсутствие небезопасного `innerHTML`.
- `node studio/test-catalog-render.mjs`: DOM-мок, открытие папок,
  нумерация, сортировка, фильтры, browser Back/Forward,
  direct deep link, пустая выдача, повтор при ошибке сети.
- Действительную работу Safari и GitHub Actions пока отдельно не
  подтверждали. Не считать CI green без завершённых шагов.
- Только каталог, его схема и тесты, главную игру и управление не менять.

**DRAFT — не сливать в main без явной команды «Сливай».**

# MINI CITY — Developer Studio 4.2.3 · каталог объектов

Данные настоящих объектов вынесены в `models/catalog.json`.
`models/catalog-utils.js` содержит проверку схемы, происхождения, путей,
отдельного GLB и статуса релиза, а также фильтры/счётчики. Интерфейс
`studio/catalog.html` + `studio/catalog.js` показывает проверяемый
реестр из семи типов существующих объектов и компонентов сцены:
пятиэтажка, городской кандидат персонажа, запасной локальный GLB,
улица/двор, деревья, фонари и скамейки.

Каталог **не создаёт модели** и не добавляет их на карту. Он не обещает
перемещение/редактирование моделей или запись изменений на GitHub из
браузера. Ссылки из карточек открывают **реальные существующие**
лаборатории или игровую сцену, а не недоделанный 3D-preview.
Для процедурных элементов улицы (дерево, фонарь, скамейка) отдельного
GLB пока нет, что явно указано. Городской анимированный GLB загружается
из внешнего источника — права и происхождение ещё не подтверждены,
релиз недоступен. Статус «Принят» означает **принят в лаборатории**,
а не «готов в production».

Новое изделие в следующем этапе проходит:
исходник и 3D-лаборатория → интерактивные тесты → проверка совместно
в игровой лаборатории → разрешение на запись в каталог в Git через PR →
только после отдельного разрешения перенос в основной город. Поля
`assetFile` и `releaseReady` запрещено указывать без подтверждения.
Тест `node models/test-catalog.mjs` сверяет каталог, исходники и
отсутствие ложных готовых GLB; `node studio/test-catalog.mjs` проверяет
HTML/JS-проводку, локальные пути и защиту от HTML-подстановки.

**Оба режима игры 4.2.2 используют ту же сцену.**
Стадия 4.2.3 добавляет только систему учёта и переходы, не увеличивает
геометрию, число draw calls и FPS-стоимость рендера. После проверки
пользователем на iPhone 12 следующий шаг — выбор конкретной модели
для детальной разработки в её лаборатории.

# MINI CITY — Developer Studio 4.2.2

## Три входа, одна сцена

Открой `studio/index.html`. На странице три режима:

1. **Лаборатория объектов** (`../lab/index.html`) — существующие отдельные
   дома и персонажи, их материалы, анимации и экспорт. Внутри двух
   объектных лабораторий есть ссылки обратно на Developer Studio.
2. **Лаборатория игры** (`../play-lab/index.html?mode=lab`) — та же
   пешеходная улица и анимированный персонаж, но с дев-панелью:
   - FPS, вызовы отрисовки, количество треугольников;
   - количество WebGL геометрий и текстур (`renderer.info`);
   - координаты X/Z персонажа, вид камеры, факт столкновения;
   - число домов, деревьев, фонарей, скамеек и прямоугольных препятствий;
   - включаемые границы столкновений (один InstancedMesh, зелёные wireframe);
   - сворачиваемая панель на мобильном Safari.
3. **Играть** (`../play-lab/index.html?mode=game`) — без инструментария
   разработчика: только игровой HUD, камера, бег и джойстик.

Кнопка «Перейти в игру / Режим разработчика» переключает режим
**в существующем WebGL canvas**, через `history.pushState`; переключатель
не создаёт второй движок, не перезагружает GLB и не сбрасывает персонажа.
Кнопки первого/третьего лица продолжают работать независимо от режима.
Кнопка браузерного «Назад» обновляет интерфейс через `popstate`.

## Техническая граница

`play-lab/studio.js` — презентация и отладка, **не собственный игровой
движок**. Его выключение не меняет `PlayerController` или его коллизии;
видимые отладочные границы — только визуализация тех же AABB-препятствий.
Панель обновляется ~раз в секунду и не выполняет UI-сбор данных в режиме
игры. В режиме игры сам WebGL renderer.info продолжает учёт стандартных
счётчиков Three.js. Включённый wireframe может снизить FPS.

Никаких допущений о том, что это полноценный редактор сцены:
пока нет создания/перемещения/сохранения объектов, систем ролей,
релизной сборки ассетов или автоматического перехода в основной город.
Не придумывать эти функции до следующего отдельного этапа.

`main`, `game.js` в корне репозитория, `district.js`,
`building-lab/building.js` и файлы персонажа не меняются.
Текущий `play-lab/game.js` содержит **одну** инстанцию Renderer и Scene.

## Проверки / приёмка

- `node play-lab/test-studio.mjs` — лаборатория/игра, URL,
  отсутствие перезагрузки/сброса, измерения, включение и скрытие
  collision-gizmos и имитация Back;
- `node studio/test-navigation.mjs` — ссылки и общие импорты,
  отсутствие копии сцены, мобильный shell;
- предыдущие тесты контроллера, направления, анимации, улицы,
  лабораторий должны остаться зелёными.

**На iPhone обязательно проверить:** оба входа из меню, переход
между режимами без потери позиции, FPS, переключение камеры,
коллизии, сворачивание отладочной панели, возвращение в каталог объектов.
Автоматические тесты с заглушками не заменяют Safari/WebGL.

До отдельного разрешения владельца: **DRAFT / DO NOT MERGE**.
